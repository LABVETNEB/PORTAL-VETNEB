### Contrato documental auditado (sólo Informes admin)

`GET /api/admin/report-workflow` autentica al admin y serializa `fileName`, pero no `mimeType`, URL ni origen. `GET /api/admin/reports/:reportId/preview-url` y `/download-url` autentican al admin, validan el ID, buscan el informe y devuelven respectivamente `{ success: true, previewUrl }` o `{ success: true, downloadUrl }`, o 404. El servicio firma `storagePath`; la respuesta no incluye tipo ni procedencia verificada. La subida admite PDF/JPEG/PNG/WebP y pasa el MIME recibido a Storage como `contentType`, pero `reports` no persiste MIME y el workflow no lo expone. El nombre o la extensión, el parámetro de una URL firmada y un `HEAD` del navegador no son metadatos autoritativos de un archivo histórico; este último además dependería de CORS de Storage. La allowlist CORS del API verifica el origen del *request* y no demuestra que el origen de la URL de Storage sea confiable para el visor.

`DocumentSource` de C15 requiere `kind`, URL HTTPS y MIME exacto (`application/pdf`, `image/jpeg`, `image/png` o `image/webp`); `validateDocumentSource` exige además que el origen de la URL coincida con una entrada HTTPS exacta de `trustedOrigins`. C16 depende de la sesión PDF válida de C15. No hay datos frontend ya autorizados suficientes para construir ese objeto sin inferencias. Los permisos actuales se mantienen en los dos GET firmados: ningún URL ni `storagePath` se incluye en el workflow, se guarda en estado persistente o se registra en esta evidencia.

Para habilitar C15/C16 hace falta **un contrato R2 separado**, sin cambiar `limit`/`offset` ni AuthN/AuthZ: sobre el GET admin de preview, después de la misma autenticación, ID y lectura autorizada, devolver un descriptor efímero `{ previewUrl, mimeType, trustedOrigin }` (o un único objeto equivalente). `mimeType` debe ser un tipo de contenido verificado del objeto real por el servidor, acotado a la allowlist; el `contentType` guardado por Storage proviene hoy del `file.mimetype` de la subida y, por sí solo, no prueba el contenido. `trustedOrigin` debe proceder de configuración de servidor y coincidir con el `origin` HTTPS de la URL firmada. Los casos sin tipo u origen fiables deben fallar cerrados con error tipado. La respuesta debe ser privada/no-cache y sin `storagePath`; la descarga conserva su endpoint y semántica. Para archivos históricos sin MIME autoritativo se necesita verificar el objeto en Storage o un backfill autorizado; no es válido asignar MIME por extensión. Archivos probables del cambio R2: `server/routes/admin-reports.fastify.ts`, `server/features/reports/application/report-route-service.ts`, `server/features/reports/composition/report-route-composition.ts`, `server/lib/supabase.ts` y sus pruebas de ruta/servicio; `drizzle/schema.ts` y migración **sólo** si se decide persistir el MIME en vez de consultar Storage. La adaptación frontend posterior afectaría `frontend/src/lib/api.ts`, `frontend/src/app/dashboard/admin/AdminReportsCard.tsx` y pruebas C17/C15/C16. No se modificó ninguno de esos archivos R2.
